# RTS Command and Simulation Contract — Milestone Record

**Status:** command intake, typed event publication, and Linux package regressions are implemented and build-verified. **Milestone acceptance remains INCOMPLETE**: representative packaged behavior passes, but the full per-case negative-state matrix and frame-delta repeatability matrix are not yet evidenced.
**Qualification target:** Unreal Engine 5.8.3, Linux Development gameplay; Linux Shipping artifact isolation only. No other platform is qualified.

## Implemented boundary

The portable contract in `Source/PolitikaCore/Rules.h` now defines `CommandRequest`: match generation, local submission sequence, participant ID, runtime issuer ID, correlation ID, and one typed `Order` variant. These identities are separate. Authored definition IDs are not used as runtime command identities. Prototype entity IDs are allocated monotonically within the match and are not reused while it is active.

The match coordinator is the intake and admission authority. The player controller continues to resolve input intent and calls compatibility submission helpers; all five helpers now construct one typed request and enter `SubmitCommand`. Requests are queued in submission order and validated at the beginning of the next 0.05-second simulation step, against current coordinator state and the current weak Actor lookups. A destroyed/missing target is rejected; dead/unavailable issuers, stale match context, inactive matches and unauthorized participants are distinguished. A rejected request does not transition the unit order. An earlier valid request in the same queue remains effective if a later request is rejected. Successive accepted requests continue to replace the current order in queue order.

Unreal adapter capabilities now derive from configured movement speed and weapon properties, not the order being requested. Map coordinates in the portable request are 2D map-space offsets from the playable minimum; conversion to/from Unreal world coordinates occurs in the match adapter. Existing unit order enum and Actor mutators remain execution-state implementation details; only the coordinator dispatches admitted player requests to them. Development-only acceptance fixtures still set up scenarios directly and are not player command paths.

The coordinator retains the existing bounded accumulator: frame delta contribution is capped at 0.25 seconds, at most five 0.05-second steps run per rendered tick, and excess backlog is discarded after the five-step cap. The authoritative order remains admission, movement, combat resolution, damage, target/death cleanup, objective evaluation. This is repeatable local sequencing, not a cross-platform determinism claim.

## Structured event publication

The match coordinator now exposes `OnGameplayEventPublished()`, a native Unreal multicast delegate carrying a const reference to the portable `GameplayEvent` variant. It broadcasts each event synchronously at the existing final simulation publication phase, after the event is appended to the current-tick snapshot. Subscribers observe authoritative results only; they cannot mutate the event payload. A subscriber that retains an event after its callback must copy it. The existing `GetPublishedEvents()` snapshot remains available for the current rendered frame, while development logs remain diagnostic-only. UE Automation verifies a native subscriber receives the typed event; the packaged interaction replay verifies event categories against the authoritative development log. This is an in-process C++ observer surface, not a Blueprint, network, replay, save, or cross-platform determinism contract.

The HUD still displays the existing last-feedback string; wiring it to event-driven presentation, adding structured identity/localization fields, and bounding or persisting history remain follow-up work. Runtime HUD is not yet an event subscriber.

## Compatibility and next boundary

No save, content, world or network schema changed. The portable `Order` alternatives remain the canonical intent payload; UE’s `EPolitikaPrototypeOrder` remains only the current execution/presentation state. Legacy `SubmitMove`, `SubmitAttack`, `SubmitStop` and `SubmitGuard` adapters are retained and delegate to common intake. Raw HUD feedback remains a presentation string; typed events are now available to in-process native C++ observers but are not yet the HUD's feedback source.

The request accepts one issuer per call and is suitable for future per-entity dispatch. Multi-selection, formation semantics, group atomicity, AI, production and networking remain deferred. Next acceptance work should add table-driven negative-state snapshots at the real coordinator boundary, repeat a scripted run under distinct rendered frame-delta schedules, and qualify a visible Shipping MainMenu startup before closing the milestone.

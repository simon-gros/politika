# POLITIKA — Changelog

Record meaningful implemented player-facing and compatibility changes under [version.json](version.json) and the [Versioning Roadmap](Docs/VERSIONING_RELEASE_MANAGEMENT_ROADMAP.md).

## Unreleased

- Formations (FORM-F3): select units and press **T** to form them into a formation in the current V shape (Line or Column); press **Y** to release them. With exactly one whole formation selected, right-click, Q and X order the formation: the server plans every member's slot and sends each member its own order. An order to a single member (for example via its control group) leaves it in the formation but lets it act on its own until the next formation move. When a member dies in transit, the survivors close ranks once, two seconds later. Each member's label shows its formation (`F1`), and the HUD shows the selected formation's shape, size and state; only the owner sees their formations. Formations end with the match and are not saved. **Network protocol 2 → 3**: clients built before this change cannot join a newer server.
- Group moves keep their spacing (FORM-F2): a right-click move or Q attack-move with several units selected now sends each unit to its own spot instead of stacking them on the clicked point. **Line** (default) puts up to 10 units side by side per rank; **Column** puts them two abreast along the direction of travel; slots are 150 cm apart and face the way the group is moving. Press **V** to switch between Line and Column; the HUD shows the current shape, and green rings briefly mark where each unit is going. Spots outside the map or on blocked ground are replaced by spare spots behind the group. A single unit still goes exactly where you click, and each unit is still admitted by the server on its own. This is not yet a persistent formation (no regrouping, stances or bonuses). Network protocol and game_version are unchanged. See the [FORM-F2 record](Docs/RTS_FORMATION_F2_GROUP_MOVE_ACCEPTANCE.md).
- Control groups 0–9 (4C-G): Ctrl+number saves the selection to a group, Shift+number adds to it, Alt+number moves units into it from other groups, and the number recalls it; press it twice quickly to centre the camera on the group. A group bar along the bottom of the HUD shows each group's size and can be clicked. Ctrl+click or double-click a unit to select every unit of that type on screen, and Tab cycles unit types in a mixed selection (grenade, reload and sprint use the active type). Groups are local to the player and never issue orders; they clear when the match ends. See the [4C-G record](Docs/RTS_CONTROL_GROUPS_4CG_ACCEPTANCE.md).
- Multi-unit selection and group orders (4C baseline): drag a box to select every own unit it touches, Shift+click to add or remove one unit, Shift+drag to add, Ctrl+drag to remove; Esc cancels a drag. Right-click, Q, X, G, R and F now order every selected unit, and the HUD shows a count ("Move: 19 of 19 units accepted") instead of one unit's result. Each unit is still admitted on its own, so one invalid unit never blocks the rest; all members move to the same point for now. The server now queues up to 16 commands plus one per living unit per player, so a full 20-unit order is no longer partly refused. Only one acknowledgement voice plays per order. Network protocol and game_version are unchanged. See the [group orders record](Docs/RTS_GROUP_ORDERS_4C_ACCEPTANCE.md).
- Multiplayer MP-2 (sixth increment): Development builds can fill each seat of the skirmish test map with up to 20 units (its cap) (`-PolitikaMPUnitScale=N`) and measure bandwidth and server step cost per phase at RTS unit counts. Packaged 1v1/2v2 runs from 52 to 802 units found that a client's default 100 KB/s send rate filled at about 400 converged units (F44). The per-connection send rate is now 400 KB/s (`DefaultEngine.ini`), and 802-unit battles peak at about 200 KB/s. Ordering a whole army still costs one long server step (F45). Owner decision U-12: 300 units per participant is the game-wide limit for the largest maps; the skirmish test map holds at most 20 per participant and passes at that cap in 1v1, 2v2 and 3v1 (82 units, under 6 % of the send rate). Earlier runs of up to 1 202 units on that map are over-density stress data only. The fixture now refuses to spawn opposing units within 900 cm of each other (F46 closed). Network protocol and game_version are unchanged. See the [MP-2 unit-scale record](Docs/RTS_MULTIPLAYER_MP2_UNIT_SCALE_ACCEPTANCE.md).

- Prototype controls: **Attack-Move is now Q and Stop is X**. W/A/S/D only pan the camera, so pressing an order no longer also nudges the camera, and holding a pan key with a unit selected no longer issues Attack-Move or Stop. Order keys are `DefaultInput.ini` action mappings, and `quality -- audit` rejects order keys that reuse a pan key. Linux Development package and 21 packaged PAC-10 replays, including 10 under CPU load: see [Test-map controls](Docs/TEST_MAP_TERRAIN.md#pac-10-hotkeypan-key-separation-resolved). Version/counters are unchanged.

- Multiplayer MP-2 (second increment): Development builds now measure each connection's bandwidth and the server's step cost, and the packaged dedicated layouts (1v1 to 2v2) are qualified under engine-emulated latency, packet loss, reordering and duplication. Network protocol and game_version are unchanged. See the [MP-2 network conditions record](Docs/RTS_MULTIPLAYER_MP2_NETWORK_CONDITIONS_ACCEPTANCE.md).

- Multiplayer MP-2 (first increment): the dedicated server now hosts packaged 2v1, 3v1 and 2v2 matches for three or four clients, and shot effects are sent per connection by team vision so they never reveal a target the viewer cannot see. **Network protocol 1 → 2**: clients built before this change are refused when joining, with a protocol-mismatch message. Development builds only; see the [MP-2 record](Docs/RTS_MULTIPLAYER_MP2_MULTICLIENT_ACCEPTANCE.md). game_version is unchanged.

- Implemented the UE 5.8.3 offline application shell, two cooked maps, persistent local profile with corruption detection, safe/reset recovery controls, canonical Rust-generated build identity, and Linux packaging. Recovered the interrupted build and fixed link exports, corrupt-profile deserialization, duplicate 4K DPI scaling, and fatal-shutdown settings writes. See [shell verification](Docs/SHELL_SKELETON.md) for compiler, package, 14-case process-check and UI evidence. This is not RTS gameplay or a public release; version/counters are unchanged.

- Integrated the newer production validators, faction roster and unit-art references with the shell. Corrected the Rust production-module path and formatting, and completed the interrupted validation record.

- Defined RTS-native historical authenticity, map-change review, 3D and visual standards, audio events, proportional validation, documentation authority, measurable performance fixtures and release acceptance. Added five source-controlled metadata ledgers and Rust schema/reference tests; performance and release claims remain blocked until real Unreal evidence exists.

- Added Rust/Cargo design-metadata regression tests, five-faction content validation, Unreal 5.8.3 source/build preflight, structured JSON diagnostic verdicts, and a staged RTS-native adoption guide; no playable engine build or hosted workflow was added.
